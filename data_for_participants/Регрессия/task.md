# Энергопотребление зданий

## Задача

Постройте регрессионную модель, которая по характеристикам здания и погодным показателям оценивает его годовое удельное энергопотребление — `site_eui`. Одна строка соответствует наблюдению за зданием в определённом году. В данных представлены жилые и коммерческие здания разных назначений.

Целевая переменная измеряется в **kBtu/ft² за год**: количество потреблённой за год энергии, разделённое на площадь здания. `kBtu` — тысяча британских тепловых единиц, `ft²` — квадратный фут. Меньшее значение означает меньшее потребление на единицу площади, однако здания разных назначений нельзя напрямую сравнивать по энергоэффективности. Таргет оставлен в исходных единицах.

Погодные признаки уже агрегированы за тот же год, за который измерен таргет. Поэтому задача — оценить энергопотребление при известных характеристиках здания и фактической погоде. Это не прогноз до начала года, когда будущая погода ещё неизвестна.

## Данные

Пути указаны относительно каталога этого Markdown-файла:

- `regression/participants/train.csv` — 53 308 строк с признаками и таргетом.
- `regression/participants/test.csv` — 22 449 строк с признаками без таргета.
- `regression/participants/data_dictionary.csv` — описание признаков.
- `regression/participants/sample_submission.csv` — шаблон ответа.
  Нули в шаблоне не являются правильными ответами.

В `train.csv` 64 столбца: 62 входных признака, идентификатор `id` и таргет
`site_eui`. В `test.csv` 63 столбца: те же признаки и `id`, без таргета.
CSV используют кодировку UTF-8, запятую как разделитель и точку как десятичный
разделитель. Пустая ячейка означает пропуск.

## Описание полей

Признаки состоят из восьми характеристик здания, местоположения и периода,
36 помесячных температур и 18 остальных погодных показателей. Погода относится
к тому же году, за который измерено энергопотребление здания.

### Идентификатор, таргет и характеристики здания

| Поле | Тип и роль | Описание и единицы измерения |
|---|---|---|
| `id` | Числовой идентификатор | Уникальный идентификатор строки. Не подтверждён как постоянный идентификатор одного здания между годами |
| `site_eui` | Числовой таргет | Годовое потребление энергии, делённое на площадь здания; kBtu/ft² за год. Есть только в `train.csv`. kBtu — тысяча британских тепловых единиц, ft² — квадратный фут |
| `Year_Factor` | Числовой код периода | Порядковый код года наблюдения; календарный год анонимизирован |
| `State_Factor` | Категориальный признак | Код штата США; соответствие кода названию штата не раскрыто |
| `building_class` | Категориальный признак | Класс здания: `Residential` — жилое, `Commercial` — коммерческое |
| `facility_type` | Категориальный признак | Назначение здания, например тип учреждения или объекта; 60 категорий в обучающей выборке |
| `floor_area` | Числовой признак | Площадь здания в квадратных футах; в квадратные метры не переводилась |
| `year_built` | Числовой признак | Календарный год постройки; присутствуют пропуски и нулевые значения |
| `energy_star_rating` | Числовой признак | Рейтинг энергоэффективности ENERGY STAR в баллах; присутствуют пропуски |
| `ELEVATION` | Числовой признак | Высота местоположения здания; единицы в исходном словаре не уточнены, значения сохранены |

`Year_Factor` и `year_built` представлены в разных шкалах: первый содержит
анонимизированный код периода, второй — календарный год.

### Остальные погодные показатели — 18 числовых признаков

| Поле | Описание | Единицы |
|---|---|---|
| `cooling_degree_days_c` | Годовая сумма превышений среднесуточной температуры над базой 18⅓ °C | °C·сутки |
| `heating_degree_days_c` | Годовая сумма недостатка среднесуточной температуры относительно базы 18⅓ °C | °C·сутки |
| `precipitation_inches` | Годовое количество осадков | Дюймы |
| `snowfall_inches` | Годовое количество выпавшего снега | Дюймы |
| `snowdepth_inches` | Годовой показатель глубины снежного покрова; способ агрегации в источнике не уточнён | Дюймы |
| `avg_temp_c` | Средняя температура за год | °C |
| `days_below_minus1C` | Число дней ниже порога ≈ −1 °C | Дни |
| `days_below_minus7C` | Число дней ниже порога ≈ −7 °C | Дни |
| `days_below_minus12C` | Число дней ниже порога ≈ −12 °C | Дни |
| `days_below_minus18C` | Число дней ниже порога ≈ −18 °C | Дни |
| `days_above_27C` | Число дней выше порога ≈ 27 °C | Дни |
| `days_above_32C` | Число дней выше порога ≈ 32 °C | Дни |
| `days_above_38C` | Число дней выше порога ≈ 38 °C | Дни |
| `days_above_43C` | Число дней выше порога ≈ 43 °C | Дни |
| `direction_max_wind_speed` | Направление ветра при максимальной скорости; 360 — север, 180 — юг | Угловые градусы |
| `direction_peak_wind_speed` | Направление ветра при пиковом порыве | Угловые градусы |

| `days_with_fog` | Число дней с туманом | Дни |

Градусо-сутки — сумма температурных разностей: для каждого дня учитывается
положительное превышение температуры над базой либо положительный недостаток
относительно базы.

Направления ветра выражены в угловых градусах и
не относятся к температуре. Площадь, осадки, снег, ветер и таргет сохранены
в исходных единицах.

## Что предсказать

Для каждой строки `test.csv` необходимо предсказать `site_eui` — годовое
удельное энергопотребление здания в kBtu/ft².

Метрика оценки — **RMSE** на исходной шкале таргета:
`sqrt(mean((y_true - y_pred) ** 2))`. Меньшее значение лучше.
Ответы теста недоступны.

## Формат результата

Файл `submission.csv` в каталоге этого Markdown-файла: CSV в UTF-8,
разделитель — запятая, без дополнительного индекса, ровно два столбца:

```csv
id,site_eui
```

Для каждого `id` из `test.csv` требуется одно конечное числовое предсказание.
Пропуски, бесконечности и повторяющиеся `id` недопустимы.
Порядок строк должен совпадать с `test.csv`.
